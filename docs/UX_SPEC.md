# UX_SPEC — 화면설계서 (UI/UX Design Specification)

- 문서 버전: v1.0
- 작성일: 2026-07-28
- 연관 문서: `PRD.md`, `SPEC.md`, `PLAN.md`
- 실행 환경: 개인 PC(Windows)에서 로컬 실행되는 FastAPI 서버 + 기본 브라우저(Chrome/Edge)로 접속하는 로컬 웹 앱. 모바일/외부 접속 대상 아님 → 반응형(모바일 대응)은 비목표, 데스크톱 브라우저 창 크기 가변만 고려.

## 0. 프론트엔드 구현 스택 (제안)

1인 개발자가 Python 중심(FastAPI/PyInstaller 단일 EXE)으로 빠르게 반복 개발하는 것이 목표이므로, 별도 프론트엔드 빌드 파이프라인(npm/webpack, React 등)은 배제하고 아래 스택을 권장한다.

| 영역 | 선택 | 이유 |
|---|---|---|
| 템플릿/렌더링 | Jinja2 (FastAPI 내장 지원) | 서버사이드 렌더링, 빌드 도구 불필요, PyInstaller 번들 용이 |
| 인터랙션 | HTMX | 페이지 새로고침 없이 부분 갱신(장비 카드, 상태 등) — JS 프레임워크 없이 구현 가능 |
| 경량 UI 로직 | Alpine.js (CDN 또는 로컬 번들) | 모달 열기/닫기, 폼 유효성 등 소규모 클라이언트 로직 |
| 실시간 갱신 | WebSocket + 소량의 vanilla JS(또는 htmx ws 확장) | 상태 브로드캐스트 수신 후 DOM 갱신 |
| 스타일 | 단일 CSS 파일 (경량 커스텀 CSS, 프레임워크 없이 또는 Pico.css/Water.css 같은 클래스리스 CSS 활용) | 빌드 없이 즉시 반영, 유지보수 단순 |

> 대안으로 React 기반 SPA도 가능하나, 빌드 파이프라인이 추가되고 PyInstaller 단일 EXE 배포 목표와 맞지 않아 채택하지 않음. 추후 UI 복잡도가 크게 증가하면 재검토.

## 1. 정보구조 (IA) / 사이트맵

```
루트 (/)
 └─ 대시보드 (홈, /)
     ├─ 장비 상세 (/devices/{id})
     │    ├─ 상태/제어 탭
     │    └─ Teams/OBTP 탭
     ├─ 장비 등록/수정 (모달, 대시보드 위에 오버레이)
     ├─ 설정 (/settings)
     └─ (Phase⑥) 로그/이력 (/logs)
```

- 내비게이션은 좌측 고정 사이드바 1단 구조로 단순화 (메뉴 depth 최소화 — 비전문가 사용자 고려).
- 장비 상세는 별도 페이지 이동이 아니라 대시보드 내 슬라이드오버(우측 패널)로 처리하여 "전체 현황을 보면서 개별 장비를 조작"하는 흐름을 유지.

## 2. 공통 레이아웃

```
┌───────────────────────────────────────────────────────────────┐
│  ● Codec Control Center                [검색....] [⚙ 설정]    │  ← 상단바 (higit-level 상태 요약 포함)
├───────────┬───────────────────────────────────────────────────┤
│           │  전체 20  |  온라인 18  |  오프라인 2  |  통화중 3   │ ← 요약 스탯 바
│  [대시보드] │───────────────────────────────────────────────────┤
│  [장비관리] │  [전체] [3F] [5F] [본사] ...  (그룹 필터 탭)         │
│  [Teams]  │───────────────────────────────────────────────────┤
│  [설정]   │                                                     │
│           │            (메인 콘텐츠 영역 — 장비 카드 그리드)       │
│           │                                                     │
└───────────┴───────────────────────────────────────────────────┘
```

- 좌측 사이드바 폭 고정(약 200px), 메인 영역 가변.
- 상단 요약 스탯 바는 항상 노출 — "지금 문제 있는 회의실이 몇 개인지" 3초 내 파악이 핵심 목표.

## 3. 디자인 시스템 — 상태 색상 규칙

장비/회의실 상태를 색으로 즉시 구분하는 것이 이 앱의 핵심 UX이므로 색상 규칙을 최우선으로 고정한다.

| 상태 | 색상(의미) | 사용처 |
|---|---|---|
| 정상/온라인 | 초록 | 카드 테두리, 뱃지 |
| 통화중 | 파랑 | 카드 상단 리본, 뱃지 |
| 음소거 | 회색 아이콘(마이크 슬래시) | 카드 내 아이콘 |
| 경고(캘린더 미연동 등) | 주황/노랑 | 뱃지 |
| 오류/오프라인 | 빨강 | 카드 테두리, 뱃지, 상단 스탯 강조 |
| 시뮬레이션 장비 | 보라 or 점선 테두리 + "SIM" 뱃지 | 실장비와 시각적으로 명확히 구분 |

- 색상만으로 구분하지 않고 아이콘 + 텍스트 라벨을 항상 병기 (색약 사용자 고려, 최소한의 접근성 확보).

## 4. 화면별 상세 설계

### 4.1 대시보드 (홈)

```
┌───────────────────────────────┐ ┌───────────────────────────────┐
│ ● 3층 대회의실        [SIM]    │ │ ● 5층 소회의실                 │
│ 상태: 통화중 🔵                │ │ 상태: 온라인 🟢                │
│ 🎤 음소거 안됨                 │ │ 🎤 음소거됨                    │
│ 마지막 갱신: 3초 전             │ │ 마지막 갱신: 5초 전             │
│ [상세보기] [🔇 Mute] [☎ 종료]  │ │ [상세보기] [🎤 Unmute] [⟳]      │
└───────────────────────────────┘ └───────────────────────────────┘
┌───────────────────────────────┐ ┌───────────────────────────────┐
│ ⛔ 본사 1층 로비                │ │ ● 본사 2층 임원실               │
│ 상태: 오프라인 🔴               │ │ 상태: 온라인 🟢                │
│ 오류: 접속 실패(타임아웃)        │ │ 다음 회의: 14:00 주간회의        │
│ 마지막 성공: 12분 전             │ │ [상세보기] [참가▶]              │
│ [재시도] [상세보기]              │ │                                │
└───────────────────────────────┘ └───────────────────────────────┘
```

- 카드 그리드는 화면 폭에 따라 2~4열 자동 배치.
- 각 카드는 가장 자주 쓰는 제어 1~2개(mute, 재시도, 회의참가)를 카드에서 바로 실행 가능하게 노출, 나머지(dial/hangup/reboot)는 상세보기에서.
- 오프라인/오류 카드는 목록 상단으로 자동 정렬(우선순위 노출).
- 그룹 필터 탭으로 층/건물별 좁혀보기, 검색창은 장비명 즉시 필터.
- 목록형(테이블) 보기 토글 옵션 제공 — 장비 수가 많을 때 한 줄 요약으로 빠르게 스캔 가능하도록.

### 4.2 장비 상세 (우측 슬라이드오버 패널)

```
┌─────────────────────────────┐
│ ✕  3층 대회의실                │
│ Poly Group 300 · SSH · SIM   │
├─────────────────────────────┤
│ [상태/제어]  [Teams/OBTP]      │
├─────────────────────────────┤
│  상태: 통화중 🔵  |  상대: xxx  │
│  음소거: 아니오                │
│                               │
│  [🔇 Mute]   [☎ Hangup]       │
│  [📞 Dial: ______] [발신]      │
│  [⟳ Reboot]  ← 확인 필요       │
│                               │
│  최근 이력(간단 로그)            │
│  14:01 상태 정상                │
│  13:58 재접속 성공              │
└─────────────────────────────┘
```

- 탭 전환: "상태/제어" ↔ "Teams/OBTP".
- reboot/hangup처럼 되돌릴 수 없는 동작은 클릭 시 confirm 모달(4.4) 경유.

### 4.3 장비 등록/수정 (모달)

```
┌───────────────────────────────────┐
│  장비 등록                     ✕   │
├───────────────────────────────────┤
│  이름        [____________]        │
│  제조사      (○ Poly  ○ Cisco)     │
│  접속방식    (○ SSH   ○ Telnet)    │
│  IP/Host     [____________]        │
│  Port        [____] (기본값 자동)   │
│  그룹(태그)  [3F ▾]                │
│  계정 ID     [____________]        │
│  계정 PW     [••••••••••••]        │
│  ☐ 시뮬레이터 장비로 등록           │
│                                     │
│  [연결 테스트]      [취소] [저장]   │
└───────────────────────────────────┘
```

- "연결 테스트" 버튼: 저장 전 실제 connect+get_status 1회 시도, 성공/실패 즉시 피드백 (오타로 인한 잘못된 등록 방지).
- 저장 시 PW는 즉시 DPAPI 암호화되어 전송/저장, 화면 새로고침 시 마스킹된 값(`••••`)만 표시하고 원문 재노출 안 함.

### 4.4 위험 동작 확인 모달 (Reboot/Hangup 공용 패턴)

```
┌───────────────────────────────┐
│  ⚠ 재부팅하시겠습니까?           │
│  "3층 대회의실" 장비가 일시적으로 │
│  응답하지 않게 됩니다.            │
│                                 │
│         [취소]   [재부팅 실행]   │
└───────────────────────────────┘
```

### 4.5 Teams / OBTP 화면 (대시보드 상단 위젯 + 장비 상세 탭)

```
┌───────────────────────────────────────────┐
│  오늘의 예정 회의                            │
├───────────────────────────────────────────┤
│ 14:00  3층 대회의실   주간 전체회의   [참가▶] │
│ 15:30  5층 소회의실   1:1 미팅        [참가▶] │
│ --:--  본사 1층 로비  캘린더 미연동 ⚠         │
└───────────────────────────────────────────┘
```

- 대시보드 상단(또는 별도 "Teams" 메뉴)에 오늘 예정 회의를 시간순으로 모아 보여줘, 곧 시작할 회의를 놓치지 않도록 지원.
- 캘린더 미연동 장비는 경고로 별도 표시.

### 4.6 설정 화면

```
┌───────────────────────────────────────┐
│  설정                                   │
├─────────────────────────────────────────┤
│  폴링 주기        [15]초                │
│  동시 접속 제한    [8]대                 │
│  명령 타임아웃      [7]초                │
│  데이터 저장 경로   C:\...\data\  [변경] │
│  ☐ 시작 시 자동으로 브라우저 열기        │
├─────────────────────────────────────────┤
│                          [저장]         │
└─────────────────────────────────────────┘
```

### 4.7 최초 실행 / 빈 상태 (Empty State)

```
┌───────────────────────────────────┐
│   등록된 장비가 없습니다.            │
│   먼저 장비를 등록하거나             │
│   시뮬레이터 장비로 체험해보세요.     │
│                                     │
│   [+ 장비 등록]   [시뮬레이터 체험]  │
└───────────────────────────────────┘
```

- 개발/데모 단계(Phase ①~②)에서 특히 유용 — 버튼 클릭 한 번으로 미리 정의된 시뮬레이터 장비 세트를 자동 등록해 즉시 화면을 채울 수 있게 지원.

## 5. 인터랙션 플로우

### 5.1 상태 갱신 플로우
1. 서버 `PollingScheduler`가 주기적으로 각 장비 상태 조회 → 변경분만 WebSocket으로 push.
2. 프론트는 해당 카드 DOM만 갱신(HTMX/WebSocket), 전체 새로고침 없음.
3. 카드에 "마지막 갱신: n초 전" 실시간 카운터 표시로 데이터 신선도를 사용자에게 인지시킴.

### 5.2 제어 명령 실행 플로우
1. 사용자가 버튼 클릭 → (위험 동작이면 4.4 확인 모달) → API 호출.
2. 버튼은 즉시 로딩 스피너 상태로 전환, 중복 클릭 방지(비활성화).
3. 응답 성공: 토스트 알림("Mute 완료") + 카드 상태 즉시 갱신. 실패: 토스트 알림(오류 사유) + 버튼 원상복구.

### 5.3 장비 등록 플로우
1. `[+ 장비 등록]` → 모달 → 입력 → `[연결 테스트]`(선택) → `[저장]`.
2. 저장 성공 시 모달 닫힘 + 대시보드에 새 카드 즉시 추가(목록 새로고침 불필요).

## 6. 사용성/접근성 원칙

- 비전문가(현장 운영자) 기준: 전문 용어(H.323, xAPI 등) 노출 최소화, 버튼 라벨은 동작 중심의 쉬운 한국어 사용("음소거", "재부팅" 등).
- 파괴적 동작(reboot, hangup, 삭제)은 항상 확인 절차를 거친다.
- 모든 상태는 색상+아이콘+텍스트 3중 표기로 오인 가능성을 낮춘다.
- 키보드 접근: 모달 ESC로 닫기, 폼 탭 이동 순서 준수 (최소 수준의 접근성).

## 7. 향후 검토 (Phase⑥ 이후, Optional)

- 다크모드 토글.
- 카드/테이블 뷰 사용자 설정 저장(로컬 preference).
- 알림음/브라우저 알림(Notification API)으로 오프라인/오류 발생 시 즉시 인지.
