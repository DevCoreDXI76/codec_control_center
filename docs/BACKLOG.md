## 로컬 포트(8765) 충돌 시 자동 재시도

**배경**: `run.py`에 `HOST`/`PORT`(127.0.0.1:8765)가 상수로 하드코딩되어 있고, 포트 사용 가능
여부를 미리 확인하지 않는다. 다른 프로세스가 8765를 이미 쓰고 있으면 `uvicorn.run()`이
`OSError`를 던지며 그대로 종료되는데, 브라우저 자동 오픈 타이머(`_open_browser_delayed`)는
서버 기동 성공 여부와 무관하게 별도 스레드에서 독립적으로 실행되므로 브라우저는 열리고
"사이트에 연결할 수 없음"만 뜬다. 콘솔(`build.spec`의 `console=True`)에 에러가 남긴 하지만,
현장 운영자 입장에서는 원인 파악이 어려운 실패 모드다.

**제안 개선**: 8765가 사용 중이면 8766, 8767 순으로 몇 개 포트를 자동으로 더 시도한 뒤,
실제로 바인딩에 성공한 포트로만 브라우저를 연다(현재처럼 무조건 8765로 열지 않도록).
모두 실패하면 콘솔에 사람이 읽을 수 있는 명확한 에러 메시지를 남긴다.

**관련 파일**: `run.py`, `docs/SPEC.md` 11절, `app/core/settings.py`(포트를 설정 가능 항목으로
노출할지는 착수 시 별도 판단).

**우선순위**: 일반 (발생 확률은 낮지만 원인 파악이 어려운 실패라 조기에 처리 권장).
