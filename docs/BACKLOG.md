## 로컬 포트(8765) 충돌 시 자동 재시도

**배경**: `run.py`에 `HOST`/`PORT`(127.0.0.1:8765)가 상수로 하드코딩되어 있고, 포트 사용 가능
여부를 미리 확인하지 않는다. 다른 프로세스가 8765를 이미 쓰고 있으면 `uvicorn.run()`이
`OSError`를 던지며 그대로 종료되는데, 브라우저 자동 오픈 타이머(`_open_browser_delayed`)는
서버 기동 성공 여부와 무관하게 별도 스레드에서 독립적으로 실행되므로 브라우저는 열리고
"사이트에 연결할 수 없음"만 뜬다. 콘솔(`build.spec`의 `console=True`)에 에러가 남긴 하지만,
현장 운영자 입장에서는 원인 파악이 어려운 실패 모드다.

**적용한 개선(v1.5.1, 2026-07-31)**: `run.py`에 `_find_available_port()` 추가 — 8765부터
8769까지 순서대로 실제 소켓 바인딩을 시도해 처음으로 성공하는 포트를 찾은 뒤, 그 포트로만
브라우저를 열고 uvicorn도 그 포트로 기동한다(기존처럼 무조건 8765로 열지 않음). 8765~8769가
모두 사용 중이면 콘솔에 "오류: ... 포트가 모두 사용 중이라 서버를 시작할 수 없습니다" 메시지를
남기고 종료 코드 1로 깨끗하게 종료한다. `SO_REUSEADDR`는 의도적으로 쓰지 않았다 — Windows에서는
POSIX와 달리 이미 다른 프로세스가 쓰고 있는 포트에도 바인딩이 성공한 것처럼 보일 수 있어서,
있는 그대로의 `bind()` 결과만 신뢰해야 실제 uvicorn 바인딩과 어긋나지 않는다. 실제로 8765를
다른 프로세스로 점유시킨 채 `run.py`를 띄워 8766으로 정상 폴백하는 것까지 확인함.
`tests/test_run.py`에 포트 탐색 함수(정상/충돌/전부충돌) + `main()` 동작(폴백 포트 사용,
브라우저 URL에 폴백 포트 반영, 전부 충돌 시 종료) 테스트 8개 추가.

**관련 파일**: `run.py`, `tests/test_run.py`, `docs/SPEC.md` 11절. 앱 포트를 설정 화면에서
직접 바꾸는 기능은 이번 범위에 넣지 않음 — 필요해지면 별도 백로그 항목으로 다시 검토.
