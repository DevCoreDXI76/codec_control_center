# PRD — 영상회의 코덱 통합 제어 앱 (Poly & Cisco Codec Control Center)

- 문서 버전: v1.0
- 작성일: 2026-07-28
- 작성자: 1인 개발자 (바이브 코딩)
- 상태: Draft

---

## 1. 배경 및 문제 정의

사내 다수의 회의실(20대 이상)에 Poly(Group/HDX 계열)와 Cisco 영상회의 코덱이 혼재되어 있다. 두 제조사의 관리 콘솔/CLI가 서로 다르고, 각 장비를 개별적으로 SSH/Telnet 접속해 상태를 확인하거나 제어해야 하는 비효율이 존재한다. 특히 회의 직전 "이 방 코덱이 꺼져 있는지, 음소거인지, 캘린더 연동이 정상인지"를 한눈에 파악할 방법이 없어 장애 대응이 늦어진다.

본 프로젝트는 Poly와 Cisco 코덱을 **하나의 로컬 웹 대시보드**에서 등록·모니터링·제어할 수 있는 통합 제어 앱을 개발한다.

## 2. 목표 (Goals)

1. Poly, Cisco 두 제조사 코덱을 동일한 UI/워크플로우로 등록하고 제어할 수 있다.
2. 20대 이상 장비의 상태(전원/네트워크/통화중/음소거/캘린더 연동 등)를 실시간에 가깝게 대시보드에서 모니터링할 수 있다.
3. 개별 장비에 대해 mute/unmute, dial, hangup, reboot 등 원격 제어를 수행할 수 있다.
4. 코덱에 등록된 Teams 캘린더(OBTP) 정보를 조회하고, 코덱을 통해 Teams 회의에 참가시킬 수 있다.
5. 장비 계정정보(IP/ID/PW)를 안전하게(평문 아님) 로컬에 저장한다.
6. 실장비 없이도 시뮬레이터로 전체 기능을 개발·검증할 수 있다.
7. 설치 파일 하나(단일 EXE)로 배포하여 별도 런타임 설치 없이 실행 가능하게 한다.

## 3. 비목표 (Non-goals)

- Microsoft Graph API 등 클라우드 기반 Teams/Exchange 연동은 범위에서 제외한다 (캘린더/OBTP는 코덱이 자체적으로 조회하는 정보만 사용).
- Poly/Cisco 외 타 제조사(예: Yealink, Logitech) 지원은 이번 범위에 포함하지 않는다.
- 다중 사용자 인증/권한 관리(RBAC), 클라우드 중앙관제 서버 구축은 이번 범위에 포함하지 않는다 (로컬 단일 사용자 대상).
- 코덱 펌웨어 업그레이드, 초기 프로비저닝(공장 초기화 등) 기능은 포함하지 않는다.

## 4. 대상 사용자

- **1차 사용자**: 본 앱을 개발·운영하는 1인 개발자 겸 사내 AV/IT 담당자.
- 시설관리자/AV 운영자가 여러 회의실의 코덱 상태를 한눈에 확인하고 즉시 조치할 수 있어야 한다.
- 비전문가도 브라우저 화면만으로 조작 가능한 수준의 UX를 목표로 한다 (CLI 지식 불필요).

## 5. 핵심 기능 요구사항

### 5.1 장비 레지스트리 (Device Registry)
- 장비 추가/수정/삭제: 이름, 제조사(Poly/Cisco), 접속 방식(SSH/Telnet), IP, 포트, 계정정보, 소속 회의실(그룹) 태그.
- 장비 목록을 그룹(층/건물 등)별로 분류하여 조회.
- 시뮬레이터 모드로 등록된 "가상 장비"와 실장비를 동일한 UI에서 구분 표시.

### 5.2 상태 대시보드
- 전체 장비를 카드/테이블 형태로 한 화면에서 조회.
- 표시 항목: 온라인 여부, 통화 상태(대기/통화중), 음소거 여부, 마지막 폴링 시각, 캘린더 연동 상태, 오류 여부.
- 장비 상태 변화 시 UI에 실시간(또는 준실시간, 폴링 기반) 반영.
- 이상 상태(오프라인, 접속 실패, 인증 실패 등) 시각적 강조.

### 5.3 원격 제어
- 개별 장비: mute/unmute, dial(발신), hangup(종료), reboot(재부팅), 상태 새로고침.
- 제어 명령 실행 결과(성공/실패/타임아웃)를 사용자에게 즉시 피드백.
- 위험 동작(reboot, hangup)은 확인(confirm) 절차를 거친다.

### 5.4 Teams 연동 (장비 경유)
- 코덱의 캘린더 등록 상태 조회 (등록됨/미등록/오류).
- 예정된 회의(OBTP: One Button To Push) 목록 조회.
- 코덱이 지원하는 방식(SIP/CVI 게이트웨이 주소 발신 또는 장비 자체 Join 명령)으로 Teams 회의 참가 실행.

### 5.5 보안 — 계정정보 저장
- IP/ID/PW 등 민감정보는 절대 평문 저장하지 않는다.
- Windows DPAPI(CryptProtectData)로 암호화하여 로컬 파일에 저장, 프로세스/사용자 컨텍스트 밖에서는 복호화 불가능해야 한다.

### 5.6 시뮬레이터
- Poly CLI 응답, Cisco xAPI 응답을 흉내 내는 모의 장비 서버를 제공.
- 실장비 접속 없이 등록/폴링/제어/캘린더 조회 전 기능을 검증 가능해야 한다.

## 6. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 성능 | 20대 이상 장비를 asyncio 기반 병렬 폴링으로 처리, UI 응답 지연 최소화 |
| 보안(네트워크) | 폴링 주기·세션 재사용 방식을 보수적으로 설계하여 보안 장비(IDS/IPS 등)의 스캔 오탐을 회피 |
| 보안(저장) | 계정정보 DPAPI 암호화, 평문 저장 금지 |
| 이식성 | Python 기반, PyInstaller로 단일 EXE 빌드, 별도 런타임 설치 불필요 |
| 확장성 | 신규 제조사 드라이버 추가 시 상위 로직/UI 변경 없이 확장 가능한 구조 |
| 신뢰성 | 명령 근거는 반드시 공식 문서(Poly Integrator Reference Guide, Cisco API Reference Guide)를 기준으로 하며 불확실한 명령은 추측 금지 |
| 검증 가능성 | 외부망에서는 시뮬레이터로 우선 검증 후 VDI 반입 실장비 테스트 진행 |

## 7. 제약사항

- 외부망(개발 환경)에서는 실제 코덱 장비에 접속할 수 없다 → 시뮬레이터 선행 개발 필수.
- Microsoft Graph API 등 클라우드 연동은 사용하지 않는다 (보안 정책상 코덱을 통한 간접 접근만 허용).
- 대상 Poly 모델은 Group/HDX 계열, Cisco 모델은 xAPI를 지원하는 모델(구체 모델명은 SPEC에서 확정)로 한정.
- 개발/배포 환경은 Windows 단일 사용자 PC 기준.

## 8. 성공 지표 (측정 가능 시)

- 등록된 20대 이상 장비의 상태를 5초 이내(폴링 주기 내) 대시보드에서 확인 가능.
- 개별 장비 제어 명령(mute/dial/hangup/reboot) 성공률 및 응답 시간 로그로 확인 가능.
- 시뮬레이터 기반 전체 기능 테스트 통과 후 VDI 실장비 테스트에서 동일 동작 확인.
- 보안 스캔(사내 IDS/IPS)에서 폴링으로 인한 오탐 미발생.

## 9. Phase별 릴리즈 범위 (개요)

| Phase | 범위 |
|---|---|
| ① | 시뮬레이터 + 접속/파싱 코어 (Poly/Cisco 공통 드라이버 인터페이스 확정) |
| ② | 장비 레지스트리 + 대시보드 MVP |
| ③ | VDI 반입, 실장비 검증 |
| ④ | Teams 스케줄 조회 / 회의 발신·참가 |
| ⑤ | Cisco 드라이버 확장 (xAPI 심화 기능) |
| ⑥ | 편의 기능 (그룹 일괄 제어, 알림, 로그/이력 등) |

상세 작업 항목은 `PLAN.md` 참조. 기술적 세부 설계는 `SPEC.md` 참조.

## 10. 오픈 이슈

- Cisco 대상 모델(구체 기종) 미확정 — Phase ⑤ 착수 전 API Reference Guide 확인 후 확정 필요.
- Teams 회의 참가 시 코덱별 SIP/CVI 게이트웨이 주소 형식 확인 필요 (사내 Teams Direct Guest Join / CVI 구성 확인).
- 폴링 주기 기본값(예: 10~30초) 및 보안팀 협의 필요 여부 확인.
